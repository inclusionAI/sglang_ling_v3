## Deployment

Use an SGLang source build that includes Ling-3.0-plus support, then replace the checkpoint paths in the command panel with your local paths or published model IDs. The panel emits a Python command so it works with a source install. See the [installation guide](/docs/get-started/install) for source setup.

Choose **FP8** for tensor and expert parallelism across eight H20-class GPUs, or **MXFP4** for tensor parallelism across four H20-class GPUs. Select **DSPARK** to add an external draft checkpoint to either target. The DSPARK combinations are awaiting end-to-end validation.

## Model and checkpoints

Ling-3.0-plus is a BailingMoeV3 hybrid KDA and MLA MoE model with 72 decoder layers. The target checkpoints tested for this recipe are a blockwise FP8 export and a mixed checkpoint with MXFP4 routed experts and FP8 dense projections. SGLang reads the context limit from each checkpoint; the commands do not override it.

| Selection | Checkpoint path to supply | Serving topology |
| --- | --- | --- |
| FP8 | Blockwise FP8 target | `--tp 8 --ep-size 8` |
| MXFP4 | Mixed MXFP4 and FP8 target | `--tp 4 --moe-runner-backend humming` |
| DSPARK | Separate Ling-3.0-plus draft, paired with either target | `--speculative-algorithm DSPARK` |

The Plus DSpark draft configuration uses a block size of 7, so each target verification window contains 8 tokens. The command sets `--enable-linear-replayssm-spec` and a 32-slot ReplaySSM ring. The draft block size is inferred from the checkpoint. A standalone draft file named `draft_model.safetensors` can share its directory with full BF16 target shards; SGLang selects the draft file and its own index for this layout.

<Note>
The MXFP4 checkpoint here uses the Humming MoE backend tested on H20. The Flash cookbook's `flashinfer_mxfp4` setting applies to its own checkpoint and hardware recipes; select the backend that matches your checkpoint and GPU.
</Note>

## Chat with thinking

The commands enable both `--reasoning-parser ling3` and `--tool-call-parser ling3`. The chat template enables thinking by default. A response returns the reasoning in `message.reasoning_content` and the answer in `message.content`.

```bash Command
curl -s http://localhost:30000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "ling-3.0-plus",
    "messages": [{"role": "user", "content": "What is 15% of 240?"}]
  }'
```

Disable thinking for an individual request with `"chat_template_kwargs": {"enable_thinking": false}`.

## Validation status

On the local Plus checkpoints, Chat Completions with thinking and the Ling3 parser scored **1283/1319 (97.27%)** on GSM8K for FP8 TP8 and **1280/1319 (97.04%)** for MXFP4 TP4. The MXFP4 run used the Humming backend. DSpark startup and accuracy with the external Plus draft are still being validated; the panel marks those cells unverified.

For the smaller model and its published checkpoints, see the [Ling-3.0-flash cookbook](/cookbook/autoregressive/InclusionAI/Ling-3.0-flash).
